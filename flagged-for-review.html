Every item carries the official link used to check it, so it can be re-checked by hand. A blank value on the site is unverified — never zero, never a guess.

Repository-level items that stay true regardless of the data:

  • Upload was incomplete. The repository was created from an upload that contained only index.html, README.md, requirements.txt, conftest.py, .gitignore and .nojekyll. The assets/, data/, src/, scripts/ and docs/ trees of the original project were absent, which is why the site returned 404s for its stylesheet and scripts. The client, the harvest and this documentation were rebuilt here. See the coordination log.
  • Original repositories are not reachable. buffedlizard55-lab/LiveScoringErrors-Pending and buffedlizard55-lab/MLB-overturned-calls return 404, so nothing from them is copied and no claim from the uploaded README is treated as evidence — uploaded README (Git history).
  • Scoring model is not recovered. The 0–100 model, its training corpus, its holdout metrics and the correlation study were not in the upload. They are not reconstructed, and no probability, SCI or hypothetical RBI is published. The rule the model would have to satisfy is quoted from the Official Baseball Rules (Rule 9.04).
  • Pending-ruling history starts empty. MLB replaces the pending marker with the corrected call, so a post-game archive cannot show cases that were resolved before it was read. The page therefore relies on the live view and on the capture workflow; the archived count is reported as it is, including zero. Event-type registry.
  • Review codes are composites. The game feed prints codes such as NH and MJ; MLB's review-reason registry publishes one- and two-letter reason codes. The site prints the raw feed code and names the reason only when the code's suffix exists in that registry. The leading letter (the review initiator) is not described, because MLB does not publish it in that endpoint.
  • Clips are links, not files. Every row links to the official play-by-play and to Baseball Savant's clip page for the play id read from the feed (example). Nothing is re-hosted, and the site does not claim a clip was watched — only that the link is the official page for that play id.
  • Bulletin is current-season only. MLB publishes scoring changes for the season it is listing; the harvest keeps every entry it reads and dates the payload so a change can be seen. Official scoring changes.

What was fixed in this session

  • Data restored from the official feeds. A real harvest (scripts/harvest.py) replaces the hand-kept sample: every completed game in the covered seasons is read, and the run-removal list is arithmetic on that record.
  • Empty views repaired. The scoring-model card was rendered empty; the decisions view only showed five hand-checked rows; the replay tab had no archive to load. All three now read the harvested payload.
  • Live replay feed added. reviews.html reads a date's reviews, pitch challenges and in-progress reviews directly from the official API, the same way the working sibling projects do.
  • Harvest automation. The workflow no longer only probes connectivity — it harvests, builds the payload, runs the offline tests and commits the JSON.
